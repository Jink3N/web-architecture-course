⚙️ Node.js, V8 & Event Loop

Scopri cosa rende Node.js speciale: un runtime leggero basato sul motore V8 di Google e un event loop che permette di gestire migliaia di richieste senza bloccare il server.

🚀 Che cos'è Node.js in parole semplici

Immagina Node.js come un "traduttore universale" che permette al tuo computer di capire ed eseguire JavaScript, proprio come fa il browser, ma per creare applicazioni server.

🎯 Analogia pratica

Se JavaScript nel browser è come un cameriere che gestisce un singolo tavolo (una pagina web), Node.js è come il maitre di un ristorante che coordina centinaia di tavoli contemporaneamente senza mai fermarsi.

🌍 Open Source e Gratuito

Creato nel 2009 da Ryan Dahl. È gratuito, il codice è pubblico e migliaia di sviluppatori contribuiscono quotidianamente.

🔄 Single-Threaded ma Potente

Un solo thread gestisce migliaia di richieste grazie all'Event Loop. Come un vigile urbano che dirige il traffico invece di fermare ogni macchina.

📦 Ecosistema NPM

Oltre 2 milioni di pacchetti pronti all'uso. È come avere una cassetta degli attrezzi infinita dove trovi sempre lo strumento giusto.

🧰 Un Linguaggio, Due Mondi

Con JavaScript puoi creare sia il frontend (ciò che vede l'utente) che il backend (il server). Come essere bilingue in un mondo globale.

� Anatomia di un runtime Node.js

Node.js è composto da più livelli che collaborano tra loro. Conoscere questi componenti ti permette di capire dove intervenire quando ottimizzi o risolvi bug complessi.

Componenti principali

Descritti nella documentazione ufficiale Node.js:

  • Motore V8 – interpreta e ottimizza il codice JavaScript.
  • Libuv – libreria C che fornisce event loop e thread pool per operazioni I/O (Event Loop Guide).
  • Bindings C++ – collegano le API di basso livello al mondo JavaScript (es. fs, net).
  • Moduli core – API standard documentate in docs/latest/api.

Thread pool configurabile

Libuv usa un pool di 4 thread per operazioni intensive (hash, compressione, DNS). Puoi configurarlo con la variabile d'ambiente UV_THREADPOOL_SIZE come descritto nella documentazione sui thread pool.

// Controlla quanti thread usa il tuo ambiente
console.log('Thread pool:', process.env.UV_THREADPOOL_SIZE ?? 'default=4');

�🧠 Il motore V8: il cuore performante

V8 è il "cervello" che trasforma il tuo codice JavaScript in istruzioni che il computer può capire. È lo stesso motore che usa Google Chrome, quindi è super testato e velocissimo.

🎭 Analogia del traduttore simultaneo

V8 è come un traduttore simultaneo a una conferenza internazionale: prende il tuo JavaScript (italiano) e lo traduce istantaneamente in "linguaggio macchina" (inglese) che il computer capisce.

🔧 Cosa fa V8 nel dettaglio?

  1. 📖 Parsing: Legge il tuo codice JS riga per riga e controlla che sia scritto correttamente (sintassi)
  2. 🏗️ Compilation: Trasforma il codice in istruzioni comprensibili al processore
  3. ⚡ Ottimizzazione: Se vede che una funzione viene chiamata spesso, la rende ancora più veloce
  4. 🗑️ Garbage Collection: Fa "le pulizie" cancellando dati non più necessari per evitare sprechi di memoria

🚀 JIT Compilation (Just-In-Time)

È come avere un assistente intelligente: mentre il programma gira, V8 osserva quali parti di codice usi di più e le "potenzia" rendendole più veloci. Non devi fare nulla tu, succede automaticamente!

// V8 nota che questa funzione viene chiamata spesso
function calcolaSconto(prezzo) {
    return prezzo * 0.9; // 10% di sconto
}

// Dopo alcune chiamate, V8 la ottimizza automaticamente

🔁 L'Event Loop: il direttore d'orchestra

L'Event Loop è come un direttore d'orchestra che coordina tutti i musicisti (le operazioni) senza mai fermarsi. È il segreto che permette a Node.js di gestire migliaia di richieste con un solo thread.

🎭 Analogia del ristorante

Immagina un cameriere in un ristorante affollato:

  • Prende l'ordine al tavolo 1 (richiesta)
  • Lo passa in cucina (operazione asincrona)
  • Non resta ad aspettare - va ai tavoli 2, 3, 4...
  • Quando il piatto è pronto, lo serve (callback)

Il cameriere non si blocca mai: è sempre in movimento!

🏗️ I componenti dell'Event Loop

📚 Call Stack (La scrivania)
Il posto dove il codice viene eseguito, una funzione alla volta. È come una pila di fogli: solo quello in cima viene processato.
🛠️ Node APIs (Gli assistenti)
Specialisti (scritti in C++) che gestiscono compiti lenti: leggere file, connessioni di rete, timer. Lavorano "dietro le quinte".
📦 Callback Queue (La sala d'attesa)
Coda dove aspettano le funzioni pronte per essere eseguite. Rispetta l'ordine di arrivo (FIFO - First In, First Out).
🔄 Event Loop (Il supervisore)
Controlla continuamente: "La scrivania è libera? C'è qualcuno in sala d'attesa?" Se sì, sposta la prossima funzione sulla scrivania.
Fase Descrizione Esempi di API
Timers Esegue callback pianificate con setTimeout/setInterval quando il timer è scaduto. Fonte: Node.js Event Loop Guide. setTimeout(fn, 0), setInterval(fn, 500)
Pending Callbacks Elabora callback per I/O differiti e operazioni di sistema. Callback interne di net, DNS async
Idle/Prepare Fasi interne usate da libuv per impostare l'iterazione successiva. —
Poll Recupera nuovi eventi I/O e li esegue; può attendere se la coda è vuota. fs.readFile, http server
Check Esegue callback registrate con setImmediate. setImmediate(() => ...)
Close Callbacks Invocata quando una risorsa si chiude ('close' events). socket.on('close'), stream

🎬 Esempio pratico passo-passo

console.log("🏁 Iniziamo!"); // ⏱️ Tempo: 0ms

setTimeout(() => {
    console.log("⏰ Timer finito!"); // ⏱️ Tempo: ~100ms
}, 100);

console.log("🔄 Sto continuando..."); // ⏱️ Tempo: 1ms

// Promise che si risolve subito
Promise.resolve().then(() => {
    console.log("✅ Promise risolta!"); // ⏱️ Tempo: 2ms
});

console.log("🏃 Finisco il sincrono"); // ⏱️ Tempo: 3ms

📊 Output finale (ordine di esecuzione)

🏁 Iniziamo!
🔄 Sto continuando...  
🏃 Finisco il sincrono
✅ Promise risolta!     ← Le Promise hanno priorità alta!
⏰ Timer finito!

Perché questo ordine? Le Promise vanno nella Microtask Queue (priorità alta), mentre setTimeout va nella Callback Queue (priorità normale).

Microtask e process.nextTick()

Oltre alle microtask delle Promise, Node.js dispone di una next tick queue gestita da process.nextTick(). Questa coda ha precedenza su tutte le altre e viene svuotata prima di tornare all'event loop (documentazione ufficiale). Evita di usarla in catene lunghe per non affamare le altre code.

🧱 Strati principali

Call Stack
Struttura LIFO (Last In, First Out) dove le funzioni vengono eseguite. È gestita da V8.
Heap
Area di memoria dove vengono salvati oggetti e dati complessi.
Callback/Task Queue
Coda di funzioni pronte ad essere eseguite quando lo stack è libero.
Microtask Queue
Coda prioritaria che contiene le callback delle Promise risolte (.then/.catch).

🔗 I Middleware: la catena di montaggio del web

Un middleware è una funzione che si interpone tra la richiesta del client e la risposta del server. È come un filtro o un checkpoint che ogni richiesta deve attraversare.

🏭 Analogia della catena di montaggio

Immagina una fabbrica di automobili: ogni operaio (middleware) fa un lavoro specifico prima di passare l'auto al prossimo. Uno monta il motore, uno verifica i freni, uno dipinge... Al termine hai un'auto completa.

🛠️ Cosa fanno i middleware più comuni?

  • 🔐 Autenticazione: verifica token/sessioni prima di proseguire (Express middleware ufficiali).
  • 📝 Logging: registra ogni richiesta per auditing (es. morgan catalogato nella documentazione Express).
  • 🛡️ Sicurezza: aggiunge header protettivi con helmet (guida ufficiale).
  • 📄 Parsing: trasforma JSON in oggetti JS tramite express.json() (API reference).
  • 💰 Rate limiting: limita il numero di richieste (es. express-rate-limit documentato su GitHub ufficiale).
Framework Firma Middleware Parametri principali Documentazione ufficiale
Express function middleware(req, res, next) req (istanza IncomingMessage), res (ServerResponse), next (funzione) Express Guide
Express (error) function errorHandler(err, req, res, next) err (oggetto errore), req, res, next Error Handling
Koa async function middleware(ctx, next) ctx (contesto), next (Promise) Koa Application

🔍 Esempio pratico: Sistema di autenticazione

// Middleware semplice per controllare autenticazione
function checkAuth(req, res, next) {
    const token = req.headers.authorization;
    
    if (!token) {
        return res.status(401).json({ 
            errore: "Token mancante - Fai login prima!" 
        });
    }
    
    if (token === "user-123-valid") {
        req.user = { id: 123, nome: "Mario Rossi" }; // Aggiungi info utente
        next(); // ✅ Passa al prossimo middleware
    } else {
        return res.status(401).json({ 
            errore: "Token non valido" 
        });
    }
}

// Middleware di logging
function logRequest(req, res, next) {
    console.log(`${new Date().toISOString()} - ${req.method} ${req.url}`);
    next(); // Passa sempre al prossimo
}

// Come si usa in Express
app.use(logRequest);           // Registra TUTTE le richieste
app.use('/api', checkAuth);    // Protegge solo le route che iniziano con /api

app.get('/api/profile', (req, res) => {
    // Qui arriva solo se checkAuth ha dato l'ok
    res.json({ 
        messaggio: `Ciao ${req.user.nome}!`,
        profilo: req.user 
    });
});

🎯 La funzione next() - Il passaggio del testimone

next() è come dire "ho finito, tocca al prossimo!" Se dimentichi di chiamarla, la richiesta rimane bloccata per sempre. Se chiami next(errore), salti direttamente alla gestione errori.

Middleware di errore (Express 4.x)

Secondo la documentazione ufficiale (Express Error Handling) un middleware di errore deve dichiarare 4 parametri. In caso contrario non verrà riconosciuto.

app.use((err, req, res, next) => {
    console.error('Errore intercettato:', err);
    res.status(500).json({ messaggio: 'Ops! Qualcosa è andato storto.' });
});

🏗️ Costruisci la tua prima catena middleware

const express = require('express');
const app = express();

// 1. Per prima cosa: parsing del JSON
app.use(express.json());

// 2. Poi: log di tutte le richieste  
app.use((req, res, next) => {
    console.log(`📝 ${req.method} ${req.url} - ${new Date()}`);
    next();
});

// 3. Middleware per aggiungere timestamp
app.use((req, res, next) => {
    req.timestamp = Date.now();
    next();
});

// 4. Route finale
app.get('/hello', (req, res) => {
    res.json({ 
        messaggio: "Ciao mondo!",
        processato_in: Date.now() - req.timestamp + "ms"
    });
});

app.listen(3000);

🤝 Perché Promises e Async sono indispensabili

Node.js basa la sua efficienza sull'event loop. Per mantenere il thread libero dobbiamo evitare operazioni bloccanti. Ecco perché è fondamentale padroneggiare Promise e async/await: sono gli strumenti che ci permettono di lavorare in armonia con questo modello.

Linee guida pratiche

  • Preferisci fs.promises alle versioni sincrone come fs.readFileSync.
  • Usa Promise.all() per eseguire query indipendenti in parallelo.
  • Non bloccare il thread con cicli while infiniti o calcoli enormi: delegali a servizi dedicati.

🚚 Caso reale: tracciamento consegne in tempo reale

Una startup logistica usa Node.js per gestire gli aggiornamenti dei corrieri. Ogni volta che un autista invia la posizione, l'evento viene gestito senza bloccare gli altri aggiornamenti grazie all'event loop.

const http = require("http");
                            const { EventEmitter } = require("events");

                            const trackingBus = new EventEmitter();

// Simula arrivo aggiornamenti dai corrieri
setInterval(() => {
    const update = {
        riderId: Math.ceil(Math.random() * 10),
        status: "in_consegna",
        position: [45.46 + Math.random() / 100, 9.19 + Math.random() / 100]
    };
    trackingBus.emit("location-update", update);
}, 1000);

const server = http.createServer((req, res) => {
    if (req.url === "/stream" && req.method === "GET") {
        res.writeHead(200, {
            "Content-Type": "text/event-stream",
            "Cache-Control": "no-cache"
        });

        const handler = update => {
            res.write(`data: ${JSON.stringify(update)}\n\n`);
        };

        trackingBus.on("location-update", handler);
        req.on("close", () => trackingBus.off("location-update", handler));
    } else {
        res.writeHead(404);
        res.end();
    }
});

server.listen(8080);

Perché funziona bene

  • Gli aggiornamenti sono gestiti come eventi: non serve un thread per ogni corriere.
  • La risposta HTTP usa Server-Sent Events per inviare dati continui al frontend.
  • L'event loop può servire centinaia di clienti contemporaneamente in modo efficiente.

🎯 Preparati agli esercizi: concetti chiave

✅ Checklist delle competenze base

Prima di passare agli esercizi pratici con Node.js, assicurati di capire questi concetti:

  • 🔄 Event Loop: Un solo thread gestisce tutto senza bloccarsi
  • 📞 Callback: Funzioni che vengono chiamate "quando è il momento"
  • 🔗 Middleware: Funzioni che processano le richieste una dopo l'altra
  • ⚡ Operazioni asincrone: Non bloccano il programma mentre aspettano
  • 🎭 next(): La funzione che passa il controllo al middleware successivo

🛠️ Strumenti che userai negli esercizi

  • Express.js: Framework per creare server web facilmente
  • fs (File System): Per leggere e scrivere file
  • http: Per creare server web "puri" (senza framework)
  • npm: Per installare pacchetti e gestire dipendenze
