🔄 Promises & Async

Capire l'asincronia in JavaScript partendo dalle basi: cosa significa non bloccare il thread, come funzionano le Promise e come semplificare il codice con async/await.

⏱️ Sincrono vs Asincrono

In un programma sincrono le istruzioni vengono eseguite una dopo l'altra. Se un'istruzione impiega tempo (es. leggere un file dal disco), tutto il resto aspetta. In un programma asincrono, invece, possiamo avviare un'operazione lenta e continuare a fare altro finché non riceviamo il risultato.

Termini chiave

  • Thread: un flusso di esecuzione. In JavaScript c'è un solo thread principale.
  • Bloccante: un'operazione che ferma il thread finché non termina.
  • Non bloccante: un'operazione che delega il lavoro e notifica quando ha finito.

Esempio intuitivo

Pensa a quando ordini una pizza. In modalità sincrona staresti fermo finché il pizzaiolo non ha finito. In modalità asincrona fai l'ordine, continui le tue attività e verrai avvisato quando la pizza è pronta.

🧩 Dal callback al "callback hell"

Prima delle Promise, l'asincronia era gestita con callback: funzioni da eseguire quando l'operazione termina. Molte callback annidate portano al cosiddetto callback hell, difficile da leggere e da gestire. 

// Callback hell (da evitare)
leggiUtente(id, function(utente) {
  leggiOrdini(utente, function(ordini) {
    leggiDettagli(ordini[0], function(dettagli) {
      console.log(dettagli);
    });
  });
});

📑 Callback: struttura, parametri e pattern ufficiali

Una callback è qualsiasi funzione passata come argomento a un'altra funzione e invocata da quest'ultima in un momento successivo. La definizione è riportata nella glossario ufficiale MDN. Il motore JavaScript non impone un numero fisso di parametri: spetta all'API che accetta la callback definire la firma.

Uso reale Firma documentata Parametri della callback Fonte ufficiale
Iterazione array Array.prototype.map(callbackFn, thisArg?) callbackFn(currentValue, index, array) MDN Array.map()
Gestione eventi DOM EventTarget.addEventListener(type, listener, options?) listener(Event) MDN addEventListener()
API Node.js (stile errore-prima) fs.readFile(path, options?, callback) callback(err, data) Node.js docs fs.readFile

Pattern comuni

  • Errore-prima (error-first): adottato dalle API core di Node.js. Il primo parametro indica l'errore (o null), il secondo il risultato.
  • Callback di progresso: alcune API, come XMLHttpRequest, invocano più volte la callback per segnalare avanzamento.
  • Callback sincrone vs asincrone: la callback può essere invocata subito (es. Array.map) o più tardi (es. eventi, I/O). 
// Callback stile Node.js documentata in fs.readFile
const fs = require("node:fs");

fs.readFile("config.json", "utf-8", (err, data) => {
  if (err) {
    console.error("Errore di lettura", err);
    return;
  }
  console.log("Contenuto:", data);
});

Il passaggio dal pattern di callback annidate alle Promise riduce la complessità della gestione del flusso, ma è fondamentale riconoscere la firma corretta delle callback per comprendere le API legacy.

🔐 Promise: il nuovo standard

Una Promise rappresenta il risultato futuro di un'operazione asincrona. È un oggetto con uno stato che può cambiare nel tempo:

Stati di una Promise

  • pending: l'operazione è in corso.
  • fulfilled: l'operazione è andata a buon fine e abbiamo un valore.
  • rejected: qualcosa è andato storto e abbiamo un errore.

Costruttore ufficiale

new Promise(executor) è definito nella sezione 27.2 dell'ECMAScript® 2026 Language Specification.

  • executor(resolve, reject) viene invocato subito e riceve due funzioni:
  • resolve(value) sposta la Promise in stato fulfilled con value.
  • reject(reason) sposta la Promise in stato rejected con reason (tipicamente un Error).

Se l'executor lancia un'eccezione, la Promise viene automaticamente rifiutata con quell'errore (comportamento documentato sia nella specifica sia in MDN Promise()). 

// Creare e consumare una Promise documentata in MDN Promise()
function leggiDato() {
  return new Promise((resolve, reject) => {
    const datoDisponibile = Math.random() > 0.2;
    if (datoDisponibile) {
      resolve("Dato pronto!");
    } else {
      reject(new Error("Impossibile leggere il dato"));
    }
  });
}

leggiDato()
  .then((dato) => console.log(dato))
  .catch((err) => console.error(err.message))
  .finally(() => console.log("Operazione terminata"));

.then(onFulfilled?, onRejected?), .catch(onRejected) e .finally(onFinally?) sono metodi documentati in MDN Promise API reference. Ognuno restituisce una nuova Promise e consente il chaining. Parametri facoltativi vengono ignorati se non forniti.

Metodo Firma Parametri principali Documentazione
.then promise.then(onFulfilled?, onRejected?) onFulfilled(value), onRejected(reason) MDN Promise.then()
.catch promise.catch(onRejected) onRejected(reason) MDN Promise.catch()
.finally promise.finally(onFinally?) onFinally() (nessun argomento garantito) MDN Promise.finally()

Attenzione a questi dettagli

  • L'executor è invocato subito: eventuali operazioni costose dovrebbero essere pianificate di conseguenza.
  • Restituire un valore da then lo incapsula nella nuova Promise; restituire un'altra Promise concatena automaticamente l'attesa.
  • Omettere catch può propagare errori non gestiti. Dal 2021, ambienti moderni generano warning su Promise rifiutate senza handler.

🧮 Promise combinators e casi d'uso

Il linguaggio fornisce metodi statici per orchestrare più Promise. Le firme ufficiali sono documentate sia nella specifica ECMAScript §27.2 sia su MDN.

Metodo Firma Comportamento Quando usarlo
Promise.all Promise.all(iterable) Si risolve quando tutte le Promise sono fulfilled; si rifiuta al primo reject. Operazioni indipendenti da eseguire in parallelo (es. caricamento risorse multiple).
Promise.allSettled Promise.allSettled(iterable) Restituisce tutte le conclusioni ({ status, value|reason }) senza fermarsi ai rifiuti. Reporting o UI che deve mostrare esiti multipli senza fallire in blocco.
Promise.any Promise.any(iterable) Si risolve con il primo valore fulfilled; si rifiuta con AggregateError se tutte rifiutate. Fallback multipli (es. più endpoint mirror fino al primo successo).
Promise.race Promise.race(iterable) Si risolve o rifiuta con il primo risultato che si manifesta. Implementare timeout o strategie "first-responder".
Promise.withResolvers (stage 3) Promise.withResolvers() Restituisce { promise, resolve, reject } già collegati. Pattern utility; disponibile in ambienti che supportano la proposta TC39 stage 3. 
// Eseguire richieste in parallelo con la firma Promise.all(iterable)
async function caricaDashboard() {
  const [utente, notifiche, preferenze] = await Promise.all([
    fetchJson("/api/user"),
    fetchJson("/api/notifications"),
    fetchJson("/api/preferences"),
  ]);
  renderDashboard({ utente, notifiche, preferenze });
}

Ogni combinator accetta un iterable: array, Set, generatori. Se si passa un valore non Promise viene coerzito con Promise.resolve, secondo la specifica.

✨ Async/Await: sintassi moderna

async/await è una sintassi introdotta in ES2017 che permette di usare le Promise scrivendo codice che sembra sincrono. Una funzione dichiarata async restituisce sempre una Promise. La parola chiave await sospende l'esecuzione della funzione finché la Promise non è risolta.

Firme ufficiali

  • Dichiarazioni async: documentate nella sezione 15.8 della specifica ECMAScript. Forme ammesse: dichiarazione (async function nome(){}), espressione, metodo di classe, metodo oggetto, async () => {}.
  • await expression: descritta in § 13.3.8. Restituisce il valore risolto della Promise o lancia l'errore rifiutato.
  • Top-level await: disponibile nei moduli ECMAScript, come specificato in § 16.5.1. 
async function mostraPrimoOrdine() {
  try {
    const utente = await leggiUtente(1);
    const ordini = await leggiOrdini(utente.id);
    console.log(ordini[0]);
  } catch (errore) {
    console.error("Qualcosa è andato storto", errore);
  }
}

// Esecuzione parallela con Promise combinators all'interno di async
async function mostraDashboard() {
  const [profilo, ordini] = await Promise.all([
    leggiUtente(1),
    leggiOrdini(1),
  ]);
  console.log({ profilo, primoOrdine: ordini.at(0) });
}

Gestione degli errori

All'interno di una funzione async usiamo try/catch per intercettare errori. È l'equivalente del blocco .catch() sulle Promise. Puoi anche gestire errori direttamente sulle Promise restituite: mostraPrimoOrdine().catch(console.error).

Checklist per principianti e intermedi

  • Ogni funzione async restituisce una Promise: anche quando return un valore semplice, viene incapsulato con Promise.resolve.
  • await funziona con qualsiasi thenable: se un oggetto implementa then, verrà trattato come una Promise.
  • Gestione parallela: preferisci Promise.all invece di await in sequenza quando non c'è dipendenza tra i risultati.
  • for await...of: consente di consumare iterabili asincroni (es. stream) ed è definito in § 14.7.5.

Per la documentazione di riferimento, consulta MDN async function e MDN await, che riassumono sintassi e casi d'uso con esempi aggiornati.

🧠 Buone pratiche per principianti

✅ Dai nomi chiari

Funzioni asincrone dovrebbero raccontare cosa restituiscono: fetchUtenti, caricaProdotti.

✅ Centralizza gli errori

Gestisci gli errori in un solo punto per evitare duplicazioni e messaggi confusi.

⚠️ Evita attese inutili

Usa Promise.all() quando puoi avviare operazioni in parallelo.

💬 Documenta i termini

Annota nel codice cosa significa “resolve” o “reject” per chi legge dopo di te.

📚 Glossario veloce

Runtime
Ambiente in cui il codice viene eseguito (browser, Node.js).
Stack
Struttura dati che tiene traccia delle funzioni in esecuzione. In JavaScript è gestita dal motore V8.
Event Loop
Meccanismo che controlla la coda di operazioni asincrone e decide quando eseguirle.
API
Interfaccia che permette a due sistemi di comunicare. In questo contesto spesso è una chiamata HTTP.

🏪 Caso reale: notifiche ordine e-commerce

In un negozio online l'utente vuole sapere quando il proprio ordine è pronto. Il backend espone un endpoint che segnala lo stato dell'ordine e invia notifiche via e-mail. Il frontend può interrogare l'API senza bloccare l'interfaccia usando async/await e gestendo time-out. 

async function controllaOrdine(orderId) {
  const controller = new AbortController();
  const timeout = setTimeout(() => controller.abort(), 5000);

  try {
    const response = await fetch(`/api/orders/${orderId}`, {
      signal: controller.signal,
    });

    if (!response.ok) {
      throw new Error(`Stato non valido: ${response.status}`);
    }

    const ordine = await response.json();
    aggiornaUI(ordine.status);
  } catch (errore) {
    mostraMessaggio("Non riusciamo a recuperare lo stato, riprova.");
    registraErrore(errore);
  } finally {
    clearTimeout(timeout);
  }
}

setInterval(() => controllaOrdine("ORD-2025-101"), 15000);

Cosa impariamo

  • Le Promise permettono di gestire timeout e abort controller senza bloccare l'utente.
  • La UI resta reattiva perché le richieste avvengono in background.
  • Centralizzare la gestione degli errori (funzioni mostraMessaggio e registraErrore) rende il codice più robusto.
