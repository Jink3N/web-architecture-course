📦 Moduli in Node.js

Scopri come organizzare il codice in file separati e riutilizzabili. Impara la differenza tra CommonJS e ES Modules e quando usare ciascun sistema.

🤔 Perché abbiamo bisogno dei moduli?

🏗️ Analogia del Lego

Immagina di costruire un castello con i Lego. Potresti fare tutto con un unico pezzo gigante, ma sarebbe:

  • ❌ Impossibile da riparare se si rompe
  • ❌ Difficile da modificare
  • ❌ Non riutilizzabile per altri progetti

I moduli sono come mattoncini Lego separati: piccoli, riutilizzabili e facili da combinare!

🧩 Riutilizzabilità

Scrivi una funzione una volta, usala in 10 progetti diversi senza riscrivere nulla.

🔒 Incapsulamento

Ogni modulo ha il suo "spazio privato". Le variabili interne non si mescolano con gli altri file.

📚 Organizzazione

Codice strutturato in file logici: auth.js, database.js, utils.js.

🤝 Collaborazione

Team diversi lavorano su moduli diversi senza conflitti nel codice.

📚 CommonJS: il sistema tradizionale

CommonJS è il sistema di moduli originale di Node.js. Usa require() per importare e module.exports o exports per esportare.

📖 Documentazione ufficiale

CommonJS è documentato in Node.js Modules API. È il sistema predefinito quando il file ha estensione .js e il package.json non specifica "type": "module".

🔧 Esportare con CommonJS

// math.js - Modulo che esporta funzioni matematiche

// Metodo 1: Esporta un oggetto con più funzioni
module.exports = {
    somma: (a, b) => a + b,
    sottrai: (a, b) => a - b,
    moltiplica: (a, b) => a * b
};

// Metodo 2: Esporta singole funzioni progressive
exports.dividi = (a, b) => {
    if (b === 0) throw new Error("Divisione per zero!");
    return a / b;
};

// Metodo 3: Esporta una singola funzione default
module.exports = function calcolatrice(operazione, a, b) {
    switch(operazione) {
        case '+': return a + b;
        case '-': return a - b;
        case '*': return a * b;
        case '/': return a / b;
        default: throw new Error("Operazione non supportata");
    }
};

📥 Importare con CommonJS

// app.js - File principale che usa il modulo

// Importa tutto l'oggetto esportato
const math = require('./math');
console.log(math.somma(5, 3));        // 8
console.log(math.moltiplica(4, 2));   // 8

// Importa con destructuring (solo le funzioni che servono)
const { somma, dividi } = require('./math');
console.log(somma(10, 5));    // 15
console.log(dividi(10, 2));   // 5

// Importa moduli core di Node.js (senza './')
const fs = require('fs');
const path = require('path');
const http = require('http');

⚠️ Differenza tra module.exports e exports

  • module.exports: l'oggetto VERO che viene esportato. Puoi sovrascriverlo completamente.
  • exports: un riferimento a module.exports. Puoi solo aggiungere proprietà, NON sostituirlo. 
// ✅ Funziona
exports.funzione = () => {};

// ❌ NON funziona - sovrascrive il riferimento locale
exports = { funzione: () => {} };

// ✅ Funziona - sovrascrive l'esportazione reale
module.exports = { funzione: () => {} };

🚀 ES Modules (ESM): lo standard moderno

ES Modules è il sistema standardizzato da ECMAScript (ES6+), supportato sia da Node.js che dai browser moderni. Usa import e export.

📖 Documentazione ufficiale

  • Node.js ECMAScript Modules - Guida completa ESM in Node.js
  • MDN JavaScript Modules - Specifica standard ES6

✅ Come attivare ES Modules

Per usare ES Modules in Node.js hai 3 opzioni:

  1. Opzione 1: Aggiungi "type": "module" nel package.json
  2. Opzione 2: Usa estensione .mjs invece di .js
  3. Opzione 3: (Per CommonJS in progetto ESM) usa .cjs 
// package.json
{
  "name": "mio-progetto",
  "version": "1.0.0",
  "type": "module"  // ← Abilita ESM per tutti i file .js
}

🔧 Esportare con ES Modules

// math.mjs (o .js con "type": "module")

// Export nominato (named export) - può avere più esportazioni
export function somma(a, b) {
    return a + b;
}

export function sottrai(a, b) {
    return a - b;
}

export const PI = 3.14159;

// Esporta tutto insieme
export { moltiplica, dividi };

function moltiplica(a, b) {
    return a * b;
}

function dividi(a, b) {
    if (b === 0) throw new Error("Divisione per zero!");
    return a / b;
}

// Export default - uno solo per modulo
export default class Calcolatrice {
    constructor() {
        this.risultato = 0;
    }
    
    somma(n) {
        this.risultato += n;
        return this;
    }
    
    get valore() {
        return this.risultato;
    }
}

📥 Importare con ES Modules

// app.mjs

// Import nominati specifici
import { somma, sottrai, PI } from './math.mjs';
console.log(somma(5, 3));      // 8
console.log(PI);               // 3.14159

// Import tutto con alias
import * as math from './math.mjs';
console.log(math.somma(10, 2));     // 12
console.log(math.moltiplica(3, 4)); // 12

// Import default
import Calcolatrice from './math.mjs';
const calc = new Calcolatrice();
console.log(calc.somma(5).somma(3).valore); // 8

// Import misto (default + nominati)
import Calcolatrice, { PI, somma } from './math.mjs';

// Import dinamico (asincrono)
async function caricaModulo() {
    const math = await import('./math.mjs');
    console.log(math.somma(2, 2));
}

💡 Import dinamici

ES Modules supporta import dinamici con import() che restituisce una Promise. Utile per lazy loading o importazioni condizionali: 

// Carica modulo solo se necessario
if (devMode) {
    const debug = await import('./debug-tools.mjs');
    debug.enableLogging();
}

⚖️ CommonJS vs ES Modules: confronto completo

Caratteristica CommonJS ES Modules (ESM)
Sintassi Import const x = require('modulo') import x from 'modulo'
Sintassi Export module.exports = x export default x
Caricamento Sincrono (bloccante) Asincrono (non bloccante)
Dinamicità Può usare require() ovunque nel codice import statico all'inizio, import() dinamico
Supporto Browser ❌ No (serve bundler tipo Webpack) ✅ Sì (nativamente nei browser moderni)
Tree-shaking ❌ Difficile ✅ Facile (rimozione codice non usato)
Estensione File .js (default in Node.js) .mjs o .js + config
Compatibilità Legacy ✅ Eccellente (tutto il vecchio codice) ⚠️ Solo Node.js 12+ e browser moderni
Binding Copia del valore esportato Riferimento live al valore esportato

🎯 Quando usare cosa?

Usa CommonJS quando:

  • ✅ Lavori su progetti Node.js esistenti che lo usano
  • ✅ Hai bisogno di import condizionali o dinamici complessi
  • ✅ Devi supportare versioni vecchie di Node.js (< 12)

Usa ES Modules quando:

  • ✅ Inizi un nuovo progetto
  • ✅ Vuoi condividere codice tra Node.js e browser
  • ✅ Vuoi beneficiare di tree-shaking e ottimizzazioni
  • ✅ Preferisci la sintassi moderna e standardizzata

🔄 Interoperabilità: mescolare CommonJS e ESM

È possibile usare moduli CommonJS in progetti ESM e viceversa, ma ci sono alcune regole.

📖 Da ESM → CommonJS

// In un file ESM (.mjs o con "type": "module")

// ✅ Funziona - import default
import fs from 'fs';  // Modulo core CommonJS

// ✅ Funziona - import da package CommonJS
import express from 'express';

// ❌ NON funziona - import nominati da CommonJS
import { readFile } from 'fs';  // Errore!

// ✅ Soluzione - usa import default poi destructuring
import fs from 'fs';
const { readFile } = fs;

📖 Da CommonJS → ESM

// In un file CommonJS (.cjs o .js senza "type": "module")

// ❌ NON funziona - require() per ESM
const math = require('./math.mjs');  // Errore!

// ✅ Funziona - import() dinamico (ritorna Promise)
async function usaModuloESM() {
    const math = await import('./math.mjs');
    console.log(math.somma(2, 3));
}

usaModuloESM();

⚠️ Regole importanti

  • ESM può importare CommonJS con import (solo default)
  • CommonJS può importare ESM solo con import() dinamico
  • Non puoi usare require() in file ESM
  • Non puoi usare import top-level in file CommonJS

🛠️ Esempio pratico: struttura progetto con moduli

Vediamo come organizzare un progetto reale usando ES Modules.

// Struttura del progetto
my-app/
├── package.json        ("type": "module")
├── src/
│   ├── index.js       (entry point)
│   ├── config/
│   │   └── database.js
│   ├── models/
│   │   └── User.js
│   ├── controllers/
│   │   └── userController.js
│   ├── routes/
│   │   └── userRoutes.js
│   └── utils/
│       ├── validation.js
│       └── logger.js
└── tests/

📁 src/utils/validation.js

// Funzioni di validazione riutilizzabili

export function isEmail(email) {
    const regex = /^[^\s@]+@[^\s@]+\.[^\s@]+$/;
    return regex.test(email);
}

export function isStrongPassword(password) {
    // Almeno 8 caratteri, una maiuscola, un numero
    return password.length >= 8 && 
           /[A-Z]/.test(password) && 
           /[0-9]/.test(password);
}

export function sanitizeInput(input) {
    return input.trim().replace(/<script>/gi, '');
}

📁 src/models/User.js

// Modello User che usa le validazioni

import { isEmail, isStrongPassword } from '../utils/validation.js';

export default class User {
    constructor(email, password) {
        if (!isEmail(email)) {
            throw new Error('Email non valida');
        }
        if (!isStrongPassword(password)) {
            throw new Error('Password troppo debole');
        }
        
        this.email = email;
        this.password = password;
        this.createdAt = new Date();
    }
    
    toJSON() {
        return {
            email: this.email,
            createdAt: this.createdAt
        };
        // ⚠️ Non esporre mai la password!
    }
}

📁 src/controllers/userController.js

// Controller che gestisce la logica degli utenti

import User from '../models/User.js';
import { sanitizeInput } from '../utils/validation.js';

export async function createUser(req, res) {
    try {
        const email = sanitizeInput(req.body.email);
        const password = req.body.password;
        
        const user = new User(email, password);
        
        // Salva nel database (esempio semplificato)
        // await db.save(user);

            success: true,
            user: user.toJSON()
        });
    } catch (error) {
        res.status(400).json({
            success: false,
            error: error.message
        });
    }
}

📁 src/routes/userRoutes.js

📁 src/index.js

✨ Vantaggi di questa struttura

  • ✅ Separazione delle responsabilità: ogni modulo ha un compito specifico
  • ✅ Riutilizzabilità: validation.js usato da più moduli
  • ✅ Testabilità: ogni funzione esportata è testabile indipendentemente
  • ✅ Scalabilità: facile aggiungere nuove route/controller
  • ✅ Manutenibilità: chiaro dove modificare il codice

🔍 Risoluzione dei moduli: come Node trova i file

Quando fai import o require(), Node.js segue regole precise per trovare il modulo.

📖 Algoritmo di risoluzione

Documentato in Node.js Module Resolution Algorithm

Tipo import Esempio Dove cerca Node.js
Core module import fs from 'fs' Moduli built-in di Node.js (priorità massima)
Percorso relativo import x from './file.js' Relativo alla posizione del file corrente
Percorso assoluto import x from '/home/user/file.js' Percorso completo del filesystem
Package node_modules import express from 'express' Cerca in node_modules/ risalendo nelle cartelle

⚠️ Differenze ESM vs CommonJS

  • ESM: devi specificare l'estensione .js per file locali
  • CommonJS: l'estensione è opzionale, Node prova .js, .json, .node 
// ESM - estensione obbligatoria
import utils from './utils.js';  // ✅

// CommonJS - estensione opzionale
const utils = require('./utils'); // ✅ trova utils.js

💡 Best practices per i moduli

✅ Un file, una responsabilità

Ogni modulo dovrebbe fare una cosa sola e farla bene. Se un file supera le 200-300 righe, considera di spezzarlo.

📛 Nomi chiari e descrittivi

Il nome del file deve far capire cosa contiene: userValidation.js è meglio di utils.js.

🔒 Esporta solo il necessario

Mantieni funzioni helper interne private. Esporta solo l'API pubblica del modulo.

📁 Struttura logica

Organizza i file in cartelle tematiche: models/, controllers/, utils/, routes/.

🔄 Evita dipendenze circolari

Se A importa B e B importa A, hai un problema. Ristruttura il codice o crea un terzo modulo.

📖 Documenta le esportazioni

Aggiungi commenti JSDoc per spiegare cosa fa ogni funzione esportata. 

/**
 * Valida un indirizzo email
 * @param {string} email - L'email da validare
 * @returns {boolean} true se valida, false altrimenti
 * @example
 *   isEmail('user@example.com')  // true
 *   isEmail('invalid')            // false
 */
export function isEmail(email) {
    const regex = /^[^\s@]+@[^\s@]+\.[^\s@]+$/;
    return regex.test(email);
}

🐛 Problemi comuni e soluzioni

❌ Errore: "Cannot find module"

Error: Cannot find module './utils'

Cause:

  • Percorso sbagliato (controlla ./ o ../)
  • Estensione mancante in ESM (aggiungi .js)
  • File non esiste o nome sbagliato

❌ Errore: "Cannot use import statement outside a module" 

SyntaxError: Cannot use import statement outside a module

Soluzione:

  • Aggiungi "type": "module" nel package.json
  • Oppure usa estensione .mjs
  • Oppure usa CommonJS (require)

❌ Errore: "require is not defined"

ReferenceError: require is not defined in ES module scope

Soluzione:

  • Stai usando require() in un file ESM
  • Usa import invece di require
  • Oppure usa createRequire:
import { createRequire } from 'module';
const require = createRequire(import.meta.url);
const config = require('./config.json');
