🚀 Express.js Framework

Il framework web più popolare per Node.js - minimalista, veloce e flessibile

🤔 Cos'è Express.js?

Express.js è un framework web minimalista e flessibile per Node.js che semplifica la creazione di server web e API REST.

🏗️ Analogia del Ristorante

Immagina Node.js come una cucina professionale con tutti gli strumenti base (forno, fornelli, pentole). Express.js è come avere:

  • 👨‍� Chef specializzati (middleware) che preparano ingredienti specifici
  • 📋 Menu organizzato (routing) per gestire gli ordini
  • 🍽️ Sistema di servizio (request/response) efficiente
  • �️ Gestione errori se qualcosa va storto in cucina

Senza Express dovresti fare tutto manualmente, con Express hai una struttura organizzata!

📊 Perché usare Express?

🎯 Semplicità

Crea un server web in 5 righe di codice invece di 50 con Node.js puro.

⚡ Velocità

Performance eccellenti: gestisce migliaia di richieste al secondo.

📦 Ecosistema

~30 milioni di download/settimana NPM. Migliaia di middleware pronti all'uso.

🏆 Standard

Usato da Netflix, Uber, PayPal e milioni di sviluppatori worldwide.

📖 Documentazione ufficiale

La documentazione completa è disponibile su expressjs.com. Express è un progetto open-source mantenuto dalla OpenJS Foundation.

� Express vs Node.js puro: confronto

Operazione Node.js puro Express.js
Creare server ~15 righe ~3 righe
Routing Manuale con if/switch app.get('/path')
Parse JSON body ~20 righe di codice app.use(express.json())
Middleware Implementazione complessa Integrato nativamente
Gestione errori Try/catch ovunque Error handler centralizzato

🚀 Installazione e Setup

⚠️ Prerequisiti

Prima di iniziare assicurati di avere:

  • ✅ Node.js installato (versione 16 o superiore) - Scarica qui
  • ✅ NPM (viene installato automaticamente con Node.js)
  • ✅ Un editor di codice (VS Code consigliato)
  • ✅ Terminal/Prompt per eseguire comandi

Verifica l'installazione: node --version e npm --version

📦 Step 1: Crea il progetto

# Crea una nuova cartella per il progetto
mkdir my-express-app
cd my-express-app

# Inizializza package.json (premi Enter per accettare i default)
npm init -y

# Il flag -y crea package.json automaticamente senza domande

💡 Cosa fa npm init -y?

Crea un file package.json con configurazioni di default. Questo file è come la "carta d'identità" del tuo progetto: contiene nome, versione, dipendenze e script.

📥 Step 2: Installa Express

# Installa Express come dipendenza
npm install express

# Installa nodemon per development (riavvia automaticamente il server)
npm install --save-dev nodemon

🤔 Differenza tra --save e --save-dev

  • npm install express → Va in dependencies (serve in produzione)
  • npm install --save-dev nodemon → Va in devDependencies (serve solo nello sviluppo)

⚙️ Step 3: Configura package.json

Apri package.json e aggiungi/modifica queste righe:

{
  "name": "my-express-app",
  "version": "1.0.0",
  "description": "La mia prima app Express",
  "type": "module",                    // ← Abilita ES Modules (import/export)
  "main": "server.js",                 // ← File principale del progetto
  "scripts": {
    "start": "node server.js",         // ← Avvio produzione
    "dev": "nodemon server.js"         // ← Avvio development (auto-reload)
  },
  "keywords": ["express", "api", "rest"],
  "author": "Il Tuo Nome",
  "license": "MIT",
  "dependencies": {
    "express": "^4.18.2"               // ← Versione installata
  },
  "devDependencies": {
    "nodemon": "^3.0.1"
  }
}

✅ Cosa significa "type": "module"?

Permette di usare la sintassi moderna import/export invece di require(). È lo standard moderno di JavaScript.

📝 Step 4: Crea il server (Hello World)

Crea un file server.js nella root del progetto:

// server.js - Il nostro primo server Express!
import express from 'express';

// Crea un'applicazione Express
const app = express();

// Definisci la porta su cui il server ascolterà
const PORT = 3000;

// Rotta base: quando qualcuno visita http://localhost:3000/
app.get('/', (req, res) => {
    res.send('🎉 Hello World! Il mio primo server Express funziona!');
});

// Avvia il server
app.listen(PORT, () => {
    console.log(`🚀 Server in ascolto su http://localhost:${PORT}`);
    console.log(`📡 Premi CTRL+C per fermarlo`);
});

🎓 Spiegazione riga per riga

  • import express from 'express' - Importa il framework Express
  • const app = express() - Crea un'applicazione Express (il tuo server)
  • const PORT = 3000 - Porta su cui il server ascolterà (puoi cambiare il numero)
  • app.get('/', ...) - Definisce cosa fare quando qualcuno visita la homepage
  • req - Request (richiesta dal client)
  • res - Response (risposta che mandiamo al client)
  • res.send(...) - Invia il testo al browser
  • app.listen(PORT, ...) - Avvia il server sulla porta specificata

▶️ Step 5: Avvia il server

# Development (con auto-reload quando modifichi il codice)
npm run dev

# Oppure production (senza auto-reload)
npm start

Vedrai nel terminal:

🚀 Server in ascolto su http://localhost:3000
📡 Premi CTRL+C per fermarlo

🌐 Step 6: Testa nel browser

✅ Verifica che funzioni

  1. Apri il browser
  2. Vai su http://localhost:3000
  3. Dovresti vedere: "🎉 Hello World! Il mio primo server Express funziona!"

Congratulazioni! Hai creato il tuo primo server Express! 🎊

🔧 Risoluzione problemi comuni

❌ Error: Cannot find module 'express'

Soluzione: Hai dimenticato npm install express

❌ Error: Port 3000 is already in use

Soluzione: Un altro programma usa già la porta 3000. Cambia const PORT = 3000 in const PORT = 3001 (o qualsiasi numero libero)

❌ SyntaxError: Cannot use import statement

Soluzione: Aggiungi "type": "module" nel package.json

🛣️ Routing in Express

🗺️ Cos'è il Routing?

Il routing è come un sistema di strade in una città: decide dove "mandare" ogni richiesta in base all'indirizzo (URL) e al metodo HTTP.

Esempio pratico: Se visiti /utenti vedrai la lista utenti, se visiti /prodotti vedrai i prodotti. Express "instrada" ogni richiesta alla funzione corretta!

📡 I Metodi HTTP: il linguaggio del web

GET 📖

Recupera dati dal server

Es: Visualizza lista prodotti

POST ➕

Crea una nuova risorsa

Es: Aggiungi nuovo prodotto

PUT 🔄

Aggiorna completamente

Es: Sostituisci tutti i dati

PATCH ✏️

Modifica parzialmente

Es: Cambia solo il prezzo

DELETE 🗑️

Elimina una risorsa

Es: Rimuovi prodotto

🎯 Routing base - Esempio passo passo

// server.js
import express from 'express';
const app = express();

// Middleware per leggere JSON nel body delle richieste
app.use(express.json());

// ═══════════════════════════════════════════════
// 📖 GET - Recupera dati
// ═══════════════════════════════════════════════

// Route 1: Homepage
app.get('/', (req, res) => {
    res.send('Benvenuto nella Homepage! 🏠');
});

// Route 2: Lista di tutti gli utenti
app.get('/utenti', (req, res) => {
    const utenti = ['Mario', 'Luigi', 'Peach', 'Toad'];
    res.json({ 
        messaggio: 'Lista utenti recuperata',
        totale: utenti.length,
        dati: utenti 
    });
});

// Route 3: Pagina "Chi siamo"
app.get('/chi-siamo', (req, res) => {
    res.send('Siamo un team di sviluppatori appassionati! 👨‍💻');
});

// ═══════════════════════════════════════════════
// ➕ POST - Crea nuovi dati
// ═══════════════════════════════════════════════

app.post('/utenti', (req, res) => {
    const nuovoUtente = req.body; // I dati arrivano nel body della richiesta
    
    console.log('Nuovo utente ricevuto:', nuovoUtente);
    
    res.status(201).json({ 
        messaggio: 'Utente creato con successo! ✅',
        utente: nuovoUtente 
    });
});

// ═══════════════════════════════════════════════
// 🔄 PUT - Aggiorna completamente
// ═══════════════════════════════════════════════

app.put('/utenti/:id', (req, res) => {
    const idUtente = req.params.id;      // Parametro dall'URL
    const datiAggiornati = req.body;      // Nuovi dati dal body
    
    res.json({ 
        messaggio: `Utente ${idUtente} aggiornato completamente`,
        nuoviDati: datiAggiornati 
    });
});

// ═══════════════════════════════════════════════
// ✏️ PATCH - Modifica parzialmente
// ═══════════════════════════════════════════════

app.patch('/utenti/:id', (req, res) => {
    const idUtente = req.params.id;
    const modifiche = req.body;           // Solo i campi da modificare
    
    res.json({ 
        messaggio: `Utente ${idUtente} modificato parzialmente`,
        modifiche: modifiche 
    });
});

// ═══════════════════════════════════════════════
// 🗑️ DELETE - Elimina
// ═══════════════════════════════════════════════

app.delete('/utenti/:id', (req, res) => {
    const idUtente = req.params.id;
    
    res.json({ 
        messaggio: `Utente ${idUtente} eliminato! 🗑️` 
    });
});

app.listen(3000, () => {
    console.log('Server avviato su http://localhost:3000');
});

🧪 Come testare queste route?

Route GET: Apri il browser e visita:

  • http://localhost:3000/ → Homepage
  • http://localhost:3000/utenti → Lista utenti
  • http://localhost:3000/chi-siamo → Chi siamo

Route POST/PUT/PATCH/DELETE: Servono strumenti come Postman, Thunder Client o curl (non puoi testarle dal browser normale).

🎯 Parametri URL: catturare valori dinamici

I parametri URL permettono di creare route dinamiche. Si definiscono con : (due punti).

// ═══════════════════════════════════════════════
// Parametri singoli
// ═══════════════════════════════════════════════

// Route con parametro :id
app.get('/utenti/:id', (req, res) => {
    const idUtente = req.params.id; // Cattura il valore dalla URL
    
    res.json({ 
        messaggio: `Stai visualizzando l'utente ${idUtente}` 
    });
});

// Prova nel browser:
// http://localhost:3000/utenti/123   → "utente 123"
// http://localhost:3000/utenti/mario → "utente mario"

// ═══════════════════════════════════════════════
// Parametri multipli
// ═══════════════════════════════════════════════

app.get('/blog/:categoria/:articolo', (req, res) => {
    const categoria = req.params.categoria;
    const articolo = req.params.articolo;
    
    res.json({ 
        messaggio: 'Articolo trovato!',
        categoria: categoria,
        articolo: articolo
    });
});

// Prova:
// http://localhost:3000/blog/tecnologia/nodejs
// → { categoria: 'tecnologia', articolo: 'nodejs' }

// ═══════════════════════════════════════════════
// Parametri con validazione (solo numeri)
// ═══════════════════════════════════════════════

app.get('/prodotti/:id(\\d+)', (req, res) => {
    // \\d+ = solo numeri (regex)
    const idProdotto = req.params.id;
    
    res.json({ 
        messaggio: `Prodotto ID ${idProdotto} (numero valido)` 
    });
});

// Prova:
// http://localhost:3000/prodotti/123  → ✅ Funziona
// http://localhost:3000/prodotti/abc  → ❌ 404 Not Found

// ═══════════════════════════════════════════════
// Parametri opzionali
// ═══════════════════════════════════════════════

app.get('/cerca/:termine?', (req, res) => {
    const termine = req.params.termine;
    
    if (termine) {
        res.json({ messaggio: `Cercando: ${termine}` });
    } else {
        res.json({ messaggio: 'Nessun termine di ricerca fornito' });
    }
});

// Prova:
// http://localhost:3000/cerca/nodejs → "Cercando: nodejs"
// http://localhost:3000/cerca        → "Nessun termine..."

🔍 Query Parameters: filtri e opzioni

I query parameters vengono dopo il ? nell'URL e servono per filtri, ordinamento, paginazione.

// Route che accetta query parameters
app.get('/prodotti', (req, res) => {
    // Cattura tutti i parametri dalla query string
    const categoria = req.query.categoria;
    const ordinamento = req.query.sort;
    const pagina = req.query.page || 1;  // Default 1 se non specificato
    
    res.json({ 
        messaggio: 'Filtri ricevuti',
        filtri: {
            categoria: categoria,
            ordinamento: ordinamento,
            pagina: pagina
        }
    });
});

// Prova nel browser:
// http://localhost:3000/prodotti?categoria=elettronica&sort=prezzo&page=2
// →
// {
//   filtri: {
//     categoria: 'elettronica',
//     ordinamento: 'prezzo',
//     pagina: '2'
//   }
// }

💡 Differenza tra Params e Query

  • Params (:id): Parte del path, obbligatori
    /utenti/123 → req.params.id
  • Query (?key=value): Dopo il ?, opzionali
    /prodotti?categoria=tech → req.query.categoria

📁 Router Modulari: organizzare il codice

Con molte route, il file server.js diventa enorme. I Router modulari permettono di organizzare le route in file separati.

🏗️ Struttura progetto con Router

my-express-app/
├── server.js           ← File principale
├── routes/             ← Cartella per le route
│   ├── utentiRoutes.js
│   ├── prodottiRoutes.js
│   └── authRoutes.js
└── package.json

Step 1: Crea file route separato

// routes/utentiRoutes.js
import express from 'express';
const router = express.Router(); // Crea un router

// Tutte queste route avranno il prefisso /utenti
router.get('/', (req, res) => {
    res.json({ messaggio: 'Lista di tutti gli utenti' });
});

router.get('/:id', (req, res) => {
    res.json({ messaggio: `Dettaglio utente ${req.params.id}` });
});

router.post('/', (req, res) => {
    res.status(201).json({ messaggio: 'Nuovo utente creato' });
});

router.delete('/:id', (req, res) => {
    res.json({ messaggio: `Utente ${req.params.id} eliminato` });
});

export default router; // Esporta il router

Step 2: Importa e usa nel server principale

// server.js
import express from 'express';
import utentiRoutes from './routes/utentiRoutes.js'; // Importa router

const app = express();

app.use(express.json());

// Monta il router con prefisso /utenti
app.use('/utenti', utentiRoutes);

// Ora tutte le route in utentiRoutes.js avranno il prefisso /utenti:
// GET  /utenti       → router.get('/')
// GET  /utenti/:id   → router.get('/:id')
// POST /utenti       → router.post('/')
// DELETE /utenti/:id → router.delete('/:id')

app.listen(3000, () => {
    console.log('Server avviato!');
});

✅ Vantaggi dei Router Modulari

  • 📁 Organizzazione: Codice diviso in file logici
  • 🔍 Leggibilità: Facile trovare le route
  • 🤝 Collaborazione: Team lavora su file diversi
  • ♻️ Riutilizzo: Stesso router in più progetti
  • 🧪 Testing: Testa ogni router separatamente

🔌 Middleware in Express

🏭 Analogia della Catena di Montaggio

Immagina una fabbrica di automobili con stazioni di assemblaggio:

  1. 🔧 Stazione 1: Monta il telaio
  2. 🚗 Stazione 2: Installa il motore
  3. 🎨 Stazione 3: Vernicia l'auto
  4. ✅ Stazione finale: Controllo qualità e consegna

I middleware sono come queste stazioni: ogni richiesta HTTP passa attraverso una "catena" di funzioni che la processano, una dopo l'altra!

🤔 Cos'è un Middleware?

Un middleware è una funzione che ha accesso a tre oggetti fondamentali:

📨 req

Request

Contiene i dati della richiesta (URL, headers, body, parametri)

📤 res

Response

Serve per inviare la risposta al client

⏭️ next

Next

Funzione che passa il controllo al prossimo middleware

🎯 Middleware base: esempio visuale

// Struttura di un middleware
function mioMiddleware(req, res, next) {
    // 1️⃣ Fai qualcosa PRIMA della route
    console.log('⏰ Richiesta ricevuta alle:', new Date().toLocaleTimeString());
    
    // 2️⃣ Modifica req o res se necessario
    req.timestampRichiesta = Date.now();
    
    // 3️⃣ Passa al prossimo middleware/route
    next(); // ⚠️ IMPORTANTE! Senza questo la richiesta si blocca
}

// Uso del middleware
app.use(mioMiddleware); // Applicato a TUTTE le route

app.get('/', (req, res) => {
    res.send('Homepage');
    // req.timestampRichiesta è disponibile qui!
});

⚠️ Regola d'oro: SEMPRE chiamare next()

Se un middleware non chiama next() e non invia una risposta con res.send(), la richiesta rimarrà "appesa" e il client riceverà timeout!

// ❌ SBAGLIATO - La richiesta si blocca
app.use((req, res, next) => {
    console.log('Logged');
    // Manca next()!
});

// ✅ CORRETTO
app.use((req, res, next) => {
    console.log('Logged');
    next(); // Passa al prossimo
});

📊 Tipi di Middleware

1️⃣ Application-level Middleware

Applicato a tutta l'applicazione o a gruppi di route.

import express from 'express';
const app = express();

// Middleware globale - applicato a TUTTE le route
app.use((req, res, next) => {
    console.log(`${req.method} ${req.url}`);
    next();
});

// Middleware per path specifico
app.use('/admin', (req, res, next) => {
    console.log('Accesso area admin');
    next();
});

// Route normali
app.get('/', (req, res) => res.send('Home'));
app.get('/admin/dashboard', (req, res) => res.send('Dashboard'));

2️⃣ Router-level Middleware

Applicato solo a un router specifico.

// routes/utentiRoutes.js
import express from 'express';
const router = express.Router();

// Middleware applicato SOLO alle route di questo router
router.use((req, res, next) => {
    console.log('Middleware del router utenti');
    next();
});

router.get('/', (req, res) => res.json({ users: [] }));

export default router;

3️⃣ Built-in Middleware (integrati in Express)

import express from 'express';
const app = express();

// 🔹 express.json() - Parsing JSON dal body
app.use(express.json());
// Ora puoi leggere req.body quando il client invia JSON

// 🔹 express.urlencoded() - Parsing form HTML
app.use(express.urlencoded({ extended: true }));
// Gestisce form submitted da HTML

// 🔹 express.static() - Serve file statici
app.use(express.static('public'));
// Serve CSS, JS, immagini dalla cartella 'public'

// Esempio con prefisso
app.use('/assets', express.static('assets'));
// http://localhost:3000/assets/logo.png

💡 Perché express.json() è importante?

Senza questo middleware, quando un client invia JSON nel body:

  • ❌ req.body sarà undefined
  • ✅ Con app.use(express.json()), req.body conterrà l'oggetto JavaScript pronto all'uso!

4️⃣ Third-party Middleware (librerie esterne)

Middleware creati dalla community, installabili con NPM.

# Installa middleware popolari
npm install cors helmet morgan compression cookie-parser
import express from 'express';
import cors from 'cors';
import helmet from 'helmet';
import morgan from 'morgan';
import compression from 'compression';
import cookieParser from 'cookie-parser';

const app = express();

// 🔐 helmet - Protegge con HTTP headers sicuri
app.use(helmet());

// 🌐 cors - Abilita richieste da altri domini
app.use(cors({
    origin: 'https://miosito.com', // Permetti solo questo dominio
    credentials: true                // Permetti cookie
}));

// 📝 morgan - Logga tutte le richieste HTTP
app.use(morgan('dev')); // Formato: GET /users 200 15.234 ms

// 🗜️ compression - Comprime le risposte (riduce banda)
app.use(compression());

// 🍪 cookie-parser - Legge i cookie facilmente
app.use(cookieParser());
// Ora puoi usare req.cookies

🛡️ Middleware essenziali per la sicurezza

  • helmet - Protegge da vulnerabilità comuni
  • cors - Controlla chi può chiamare la tua API
  • express-rate-limit - Previene attacchi DDoS
  • express-validator - Valida input utente

5️⃣ Custom Middleware (creati da te)

Esempio 1: Logger personalizzato
// middleware/logger.js
const logger = (req, res, next) => {
    const ora = new Date().toLocaleTimeString('it-IT');
    const metodo = req.method;
    const url = req.url;
    
    console.log(`[${ora}] ${metodo} ${url}`);
    
    // Log anche quando la risposta è inviata
    res.on('finish', () => {
        console.log(`  ↳ Status: ${res.statusCode}`);
    });
    
    next();
};

export default logger;

// server.js
import logger from './middleware/logger.js';
app.use(logger);
Esempio 2: Middleware di autenticazione
// middleware/auth.js
const autenticaUtente = (req, res, next) => {
    // Leggi il token dall'header Authorization
    const token = req.headers.authorization;
    
    // Verifica se il token esiste
    if (!token) {
        return res.status(401).json({ 
            errore: 'Accesso negato! Token mancante' 
        });
    }
    
    // Verifica se il token è valido (esempio semplificato)
    if (token === 'Bearer token-segreto-123') {
        // Token valido: aggiungi info utente a req
        req.utente = { 
            id: 1, 
            nome: 'Mario', 
            ruolo: 'admin' 
        };
        next(); // Procedi alla route
    } else {
        return res.status(403).json({ 
            errore: 'Token non valido!' 
        });
    }
};

export default autenticaUtente;

// Uso in route protette
import autenticaUtente from './middleware/auth.js';

// Route pubblica (non richiede auth)
app.get('/pubblico', (req, res) => {
    res.json({ messaggio: 'Visibile a tutti' });
});

// Route protetta (richiede auth)
app.get('/profilo', autenticaUtente, (req, res) => {
    // req.utente è disponibile qui!
    res.json({ 
        messaggio: 'Profilo privato',
        utente: req.utente 
    });
});
Esempio 3: Middleware di validazione
// middleware/validation.js
export const validaUtente = (req, res, next) => {
    const { username, email, password } = req.body;
    
    // Array per raccogliere gli errori
    const errori = [];
    
    // Validazione username
    if (!username || username.length < 3) {
        errori.push('Username deve avere almeno 3 caratteri');
    }
    
    // Validazione email
    const emailRegex = /^[^\s@]+@[^\s@]+\.[^\s@]+$/;
    if (!email || !emailRegex.test(email)) {
        errori.push('Email non valida');
    }
    
    // Validazione password
    if (!password || password.length < 8) {
        errori.push('Password deve avere almeno 8 caratteri');
    }
    
    // Se ci sono errori, invia risposta 400
    if (errori.length > 0) {
        return res.status(400).json({ 
            errore: 'Validazione fallita',
            dettagli: errori 
        });
    }
    
    // Tutto ok, procedi
    next();
};

// Uso

🎬 Ordine di esecuzione dei Middleware

⚠️ L'ordine è FONDAMENTALE!

I middleware vengono eseguiti nell'ordine in cui sono definiti con app.use().

import express from 'express';
const app = express();

// 1️⃣ Primo middleware - esegue per PRIMO
app.use((req, res, next) => {
    console.log('1️⃣ Primo middleware');
    next();
});

// 2️⃣ Secondo middleware
app.use((req, res, next) => {
    console.log('2️⃣ Secondo middleware');
    next();
});

// 3️⃣ Route finale
app.get('/', (req, res) => {
    console.log('3️⃣ Route handler');
    res.send('Risposta');
});

// Output in console quando visiti /:
// 1️⃣ Primo middleware
// 2️⃣ Secondo middleware
// 3️⃣ Route handler

🚨 Error Handling Middleware

I middleware di gestione errori hanno una firma speciale: 4 parametri invece di 3.

// Error handler - DEVE avere 4 parametri (err, req, res, next)
const errorHandler = (err, req, res, next) => {
    console.error('❌ Errore catturato:', err.message);
    console.error('Stack trace:', err.stack);
    
    // Errore con status code personalizzato
    if (err.statusCode) {
        return res.status(err.statusCode).json({
            errore: err.message
        });
    }
    
    // Errore generico 500
    res.status(500).json({
        errore: 'Qualcosa è andato storto sul server',
        dettaglio: err.message
    });
};

// 404 handler (risorsa non trovata)
app.use((req, res) => {
    res.status(404).json({
        errore: '404 - Risorsa non trovata',
        url: req.url
    });
});

// Error handler - SEMPRE come ULTIMO middleware
app.use(errorHandler);

// Come usare l'error handler
app.get('/errore', (req, res, next) => {
    const errore = new Error('Qualcosa è andato storto!');
    errore.statusCode = 400;
    next(errore); // Passa l'errore all'error handler
});

// Con async/await
app.get('/dati', async (req, res, next) => {
    try {
        const dati = await fetchDatiDalDatabase();
        res.json(dati);
    } catch (error) {
        next(error); // Passa errori async all'handler
    }
});

✅ Best Practice Middleware

  1. 🔝 Metti middleware generici (logger, cors) all'inizio
  2. 📦 express.json() prima delle route che ricevono JSON
  3. 🛣️ Definisci le route
  4. 🚫 404 handler dopo tutte le route
  5. 🚨 Error handler come ULTIMO middleware
// ✅ Ordine corretto
app.use(logger);           // 1. Logger
app.use(cors());           // 2. CORS
app.use(express.json());   // 3. Body parser
app.use('/api', routes);   // 4. Route
app.use(notFoundHandler);  // 5. 404
app.use(errorHandler);     // 6. Errori

📡 Request e Response - Gli oggetti fondamentali

💌 Analogia della Lettera

Request (req) è come una lettera che ricevi: contiene il mittente, il contenuto, quando è arrivata, ecc.

Response (res) è come la tua risposta: decidi cosa scrivere, come formattarla, e la invii indietro!

📨 Oggetto Request (req) - Cosa contiene

app.get('/info', (req, res) => {
    // 🔍 Ispeziona tutto quello che ricevi
    console.log({
        // 1️⃣ Parametri URL dinamici
        params: req.params,        
        // /utenti/:id → req.params.id
        
        // 2️⃣ Query string
        query: req.query,          
        // /cerca?q=nodejs → req.query.q = 'nodejs'
        
        // 3️⃣ Body della richiesta (POST/PUT)
        body: req.body,            
        // { username: 'mario', email: '...' }
        
        // 4️⃣ Headers HTTP
        headers: req.headers,      
        // { 'content-type': 'application/json', ... }
        
        // 5️⃣ Metodo HTTP
        method: req.method,        
        // 'GET', 'POST', 'PUT', 'DELETE', etc.
        
        // 6️⃣ URL completo richiesto
        url: req.url,              
        // '/prodotti?categoria=tech'
        
        // 7️⃣ Path senza query
        path: req.path,            
        // '/prodotti' (senza ?categoria=tech)
        
        // 8️⃣ Hostname del server
        hostname: req.hostname,    
        // 'localhost' o 'miosito.com'
        
        // 9️⃣ IP del client
        ip: req.ip,                
        // '192.168.1.10'
        
        // 🔟 Protocollo
        protocol: req.protocol,    
        // 'http' o 'https'
        
        // 🍪 Cookie (richiede cookie-parser)
        cookies: req.cookies       
        // { sessionId: 'abc123' }
    });
    
    res.json({ messaggio: 'Controlla la console!' });
});

💻 Esempio completo MVC - Sistema Utenti

1️⃣ Model - models/User.js

// 📦 MODEL: Definisce la struttura dati e la logica
let users = []; // Simulazione database (in produzione usa MongoDB, PostgreSQL, etc.)
let nextId = 1;

export const User = {
    // 🔍 Trova tutti gli utenti
    findAll() {
        return users;
    },
    
    // 🔍 Trova utente per ID
    findById(id) {
        return users.find(user => user.id === parseInt(id));
    },
    
    // ➕ Crea nuovo utente
    create(userData) {
        const newUser = {
            id: nextId++,
            ...userData,
            createdAt: new Date().toISOString()
        };
        users.push(newUser);
        return newUser;
    },
    
    // ✏️ Aggiorna utente
    update(id, updates) {
        const index = users.findIndex(u => u.id === parseInt(id));
        if (index === -1) return null;
        
        users[index] = { ...users[index], ...updates };
        return users[index];
    },
    
    // ❌ Elimina utente
    delete(id) {
        const index = users.findIndex(u => u.id === parseInt(id));
        if (index === -1) return false;
        
        users.splice(index, 1);
        return true;
    }
};

2️⃣ Controller - controllers/userController.js

// 🎮 CONTROLLER: Gestisce la logica delle richieste
import { User } from '../models/User.js';

export const userController = {
    // GET /api/users - Lista tutti
    getAllUsers(req, res) {
        try {
            const users = User.findAll();
            res.json({ 
                success: true, 
                count: users.length,
                data: users 
            });
        } catch (error) {
            res.status(500).json({ 
                success: false, 
                error: error.message 
            });
        }
    },
    
    // GET /api/users/:id - Singolo utente
    getUserById(req, res) {
        try {
            const user = User.findById(req.params.id);
            
            if (!user) {
                return res.status(404).json({ 
                    success: false, 
                    error: 'Utente non trovato' 
                });
            }
            
            res.json({ success: true, data: user });
        } catch (error) {
            res.status(500).json({ 
                success: false, 
                error: error.message 
            });
        }
    },
    
    // POST /api/users - Crea nuovo
    createUser(req, res) {
        try {
            const { username, email } = req.body;
            
            // Validazione semplice
            if (!username || !email) {
                return res.status(400).json({ 
                    success: false, 
                    error: 'Username e email obbligatori' 
                });
            }
            
            const newUser = User.create({ username, email });
            res.status(201).json({ 
                success: true, 
                data: newUser 
            });
        } catch (error) {
            res.status(500).json({ 
                success: false, 
                error: error.message 
            });
        }
    },
    
    // PUT /api/users/:id - Aggiorna
    updateUser(req, res) {
        try {
            const updatedUser = User.update(req.params.id, req.body);
            
            if (!updatedUser) {
                return res.status(404).json({ 
                    success: false, 
                    error: 'Utente non trovato' 
                });
            }
            
            res.json({ success: true, data: updatedUser });
        } catch (error) {
            res.status(500).json({ 
                success: false, 
                error: error.message 
            });
        }
    },
    
    // DELETE /api/users/:id - Elimina
    deleteUser(req, res) {
        try {
            const deleted = User.delete(req.params.id);
            
            if (!deleted) {
                return res.status(404).json({ 
                    success: false, 
                    error: 'Utente non trovato' 
                });
            }
            
            res.json({ 
                success: true, 
                message: 'Utente eliminato' 
            });
        } catch (error) {
            res.status(500).json({ 
                success: false, 
                error: error.message 
            });
        }
    }
};

⚠️ Attenzione alla Sicurezza!

Le applicazioni web sono costantemente sotto attacco. Segui sempre queste regole fondamentali!

🔒 1. Usa Helmet per la sicurezza HTTP

// Installa: npm install helmet
import helmet from 'helmet';

app.use(helmet());
// Imposta automaticamente headers di sicurezza come:
// - Content-Security-Policy
// - X-Frame-Options (previene clickjacking)
// - X-Content-Type-Options
// - Strict-Transport-Security (HSTS)
// - X-XSS-Protection

🚦 2. Rate Limiting - Previeni attacchi bruteforce

// Installa: npm install express-rate-limit
import rateLimit from 'express-rate-limit';

const limiter = rateLimit({
    windowMs: 15 * 60 * 1000, // 15 minuti
    max: 100,                  // Max 100 richieste per IP
    message: 'Troppe richieste, riprova tra 15 minuti'
});

// Applica a tutte le route
app.use(limiter);

// Oppure solo a route sensibili
app.post('/login', limiter, (req, res) => {
    // Login logic
});

✅ 3. Validazione Input - Mai fidarsi del client

// Installa: npm install express-validator
import { body, validationResult } from 'express-validator';

app.post('/registrazione',
    // Array di validazioni
    [
        body('email')
            .isEmail()
            .withMessage('Email non valida'),
        body('password')
            .isLength({ min: 8 })
            .withMessage('Password minimo 8 caratteri'),
        body('username')
            .trim()
            .notEmpty()
            .withMessage('Username obbligatorio')
    ],
    (req, res) => {
        // Controlla errori validazione
        const errors = validationResult(req);
        if (!errors.isEmpty()) {
            return res.status(400).json({ errors: errors.array() });
        }
        
        // Dati validati, procedi...
        res.json({ message: 'Registrazione OK' });
    }
);

🎯 Punti Chiave Express.js

  1. Express è minimalista: Ti dà le basi, tu aggiungi quello che serve
  2. Routing potente: Gestisci facilmente URL complessi con parametri
  3. Middleware è tutto: Ogni richiesta passa attraverso una catena di middleware
  4. Req/Res objects: Contengono tutto quello che ti serve per gestire richieste
  5. MVC consigliato: Separa Model, Controller, Routes per codice pulito
  6. Sicurezza prima di tutto: Usa helmet, validazione, rate limiting
  7. Environment variables: Mai hardcodare credenziali nel codice
  8. Error handling: Middleware con 4 parametri (err, req, res, next)
  9. Ecosistema ricco: Migliaia di middleware pronti all'uso su npm
  10. Pratica costante: Crea progetti reali per padroneggiare Express!

Esempio configurazione sicurezza

import express from 'express';
import helmet from 'helmet';
import rateLimit from 'express-rate-limit';
import { body, validationResult } from 'express-validator';

const app = express();

// Helmet per headers sicuri
app.use(helmet());

// Rate limiting
const limiter = rateLimit({
    windowMs: 15 * 60 * 1000, // 15 minuti
    max: 100 // max 100 richieste
});

app.use('/api/', limiter);

// Validazione input
app.post('/users',
    body('email').isEmail(),
    body('password').isLength({ min: 8 }),
    (req, res) => {
        const errors = validationResult(req);
        if (!errors.isEmpty()) {
            return res.status(400).json({ errors: errors.array() });
        }
        res.json({ success: true });
    }
);

✅ Da ricordare

  • Express è un framework minimalista e non-opinionated
  • Il middleware è il concetto fondamentale (pipeline di funzioni)
  • Usare next() per passare al prossimo middleware
  • Error handler deve avere 4 parametri (err, req, res, next)
  • Router modulari per organizzare il codice
  • Separare logica in controllers, models, routes
  • Usare middleware di sicurezza (helmet, cors, rate-limit)
  • Environment variables per configurazioni sensibili
  • Async/await per operazioni asincrone
