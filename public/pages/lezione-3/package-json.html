⚙️ Package.json & NPM

Il cuore di ogni progetto Node.js: configurazione, dipendenze, scripts e metadata

📦 Cos'è package.json?

Il package.json è il file di configurazione principale di un progetto Node.js. Contiene metadata, dipendenze, script e configurazioni. Documentazione: NPM Docs

🚀 Creare un package.json

# Metodo interattivo (fa domande)
npm init

# Metodo rapido (usa defaults)
npm init -y

# Con scope (per package privati/org)
npm init --scope=@myorg

🔑 Campi essenziali

{
  "name": "my-app",
  "version": "1.0.0",
  "description": "La mia applicazione Node.js",
  "main": "index.js",
  "type": "module",
  "scripts": {
    "start": "node index.js",
    "dev": "nodemon index.js",
    "test": "jest"
  },
  "keywords": ["api", "rest", "nodejs"],
  "author": "Il Tuo Nome",
  "license": "MIT",
  "dependencies": {
    "express": "^4.18.2"
  },
  "devDependencies": {
    "nodemon": "^3.0.1"
  }
}

📖 Spiegazione campi

Campo Descrizione Esempio
name Nome univoco del package (lowercase, no spazi) "my-awesome-app"
version Versione semantica (MAJOR.MINOR.PATCH) "1.2.3"
main Entry point quando qualcuno importa il tuo package "dist/index.js"
type "module" per ESM, "commonjs" per CJS "module"
scripts Comandi eseguibili con npm run Vedi sotto

📜 Scripts: automatizza tutto

Gli script sono comandi personalizzati che puoi eseguire con npm run nome-script

"scripts": {
  "start": "node index.js",
  "dev": "nodemon --watch src index.js",
  "build": "tsc && node dist/index.js",
  "test": "jest --coverage",
  "test:watch": "jest --watch",
  "lint": "eslint src/**/*.js",
  "format": "prettier --write src/**/*.js",
  "clean": "rm -rf dist node_modules"
}

🎯 Script comuni

  • npm start - Avvia l'app (shortcut per npm run start)
  • npm test - Esegue i test (shortcut)
  • npm run dev - Modalità sviluppo con hot-reload
  • npm run build - Compila il progetto
  • npm run lint - Controlla errori di stile

🔗 Script concatenati

"scripts": {
  "prebuild": "npm run clean",
  "build": "tsc",
  "postbuild": "npm run test",
  "deploy": "npm run build && npm run upload"
}

📦 Gestione dipendenze

Tipi di dipendenze

Tipo Comando Quando usarlo
dependencies npm install express Package necessari in produzione
devDependencies npm install -D nodemon Tool di sviluppo (test, lint, build)
peerDependencies Manuale nel package.json Compatibilità con altri package
optionalDependencies npm install --save-optional Feature opzionali che possono fallire

🔢 Versioni semantiche (Semver)

"dependencies": {
  "express": "4.18.2",      // Esatta
  "lodash": "^4.17.21",     // Compatibile (^4.x.x)
  "axios": "~1.4.0",        // Patch (1.4.x)
  "dotenv": "*",            // Qualsiasi (sconsigliato!)
  "mysql": ">=2.18.1",      // Maggiore o uguale
  "redis": "2.x"            // Range 2.0.0 - 2.99.99
}

Simboli versioni

  • ^ (caret): accetta MINOR e PATCH updates (^1.2.3 → 1.x.x)
  • ~ (tilde): accetta solo PATCH updates (~1.2.3 → 1.2.x)
  • Nessuno: versione esatta (1.2.3 → 1.2.3)

🛠️ Comandi NPM essenziali

# Installazione
npm install                    # Installa tutte le dipendenze
npm install express            # Installa e salva in dependencies
npm install -D jest            # Installa in devDependencies
npm install -g nodemon         # Installa globalmente

# Aggiornamento
npm update                     # Aggiorna tutti i package
npm update express             # Aggiorna package specifico
npm outdated                   # Mostra package obsoleti

# Rimozione
npm uninstall express          # Rimuove package
npm uninstall -D jest          # Rimuove da devDependencies
npm prune                      # Rimuove package non usati

# Informazioni
npm list                       # Lista dipendenze installate
npm list --depth=0             # Solo top-level
npm view express               # Info su un package
npm search api                 # Cerca package

# Sicurezza
npm audit                      # Controlla vulnerabilità
npm audit fix                  # Corregge vulnerabilità
npm audit fix --force          # Fix forzato (breaking changes)

# Cache
npm cache clean --force        # Pulisce cache NPM

🔒 Lock file: package-lock.json

Il package-lock.json registra le versioni ESATTE di tutte le dipendenze installate (incluse transitive).

✅ Perché è importante

  • Garantisce build riproducibili su macchine diverse
  • Velocizza l'installazione (cache ottimizzata)
  • Previene "works on my machine" syndrome
  • Committa SEMPRE il lock file nel repo

🌍 Variabili d'ambiente

Usa il package dotenv per gestire configurazioni sensibili

# .env (NON committare questo file!)
DATABASE_URL=postgresql://localhost/mydb
API_KEY=supersecretkey123
PORT=3000
NODE_ENV=development
// index.js
import 'dotenv/config';  // o require('dotenv').config()

console.log(process.env.DATABASE_URL);
console.log(process.env.PORT);          // "3000"
console.log(process.env.NODE_ENV);      // "development"
# .gitignore - SEMPRE ignorare .env
node_modules/
.env
.env.local
*.log

💡 Best practices

📌 Usa versioni specifiche

In produzione usa versioni esatte o ^ per evitare breaking changes improvvisi

🔒 Committa package-lock.json

Garantisce che tutti abbiano le stesse versioni delle dipendenze

🧪 Separa dev e prod

Tool di test e build vanno in devDependencies per ridurre bundle size

🔍 Audit regolarmente

Esegui npm audit settimanalmente per sicurezza
